# Usability Testing and Product Validation

A polished screen is not automatically an easy screen. Validate task success with people who were not involved in building the feature.

## Test principles
- Test real tasks, not opinions about whether a screen looks nice.
- Give users a goal without explaining the interface.
- Observe where they pause, mis-tap, backtrack or ask for help.
- Avoid leading questions.
- Test both first-time and returning-user flows.
- Include phone and tablet use where relevant.

## Core tasks to test
1. Find today's next useful action.
2. Start, pause, resume and complete a focus session.
3. Create a task and select a category.
4. Log a routine anchor and edit its target time.
5. Record sleep and mood/energy.
6. Log a medication as taken or skipped.
7. Create and edit an alarm.
8. Capture a distracting thought and return to focus.
9. Understand Health Connect permissions and source attribution.
10. Export/restore local data and understand cloud-sync availability.

## Measures
- Task completion rate.
- Time to first successful action.
- Mis-tap and backtrack count.
- Help requests.
- User confidence after the task.
- Accessibility blockers.
- Whether users understand what data is local vs connected vs remote.

## Release thresholds
Do not set arbitrary pass percentages before a baseline. Record the baseline first, prioritize critical failures, then retest. A critical safety, data-loss or false-success issue blocks release regardless of average score.

## Feedback loop
Every finding becomes one of:
- Confirmed defect with reproduction steps.
- Usability issue with user evidence.
- Preference request.
- New product hypothesis.

Link findings to GitHub issues and close them only after retesting.
